# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**DASIGConnect** is a capstone project (Team `2526-sem2-it332-38`, CIT-U) - a web-based Social Media Content Workflow and Scheduling Management System for the **DOST Academe-Science and Innovation Group (DASIG)** under DOST Region 7.

It replaces ad hoc coordination between DASIG member HEIs with a structured workflow: contributors submit event content, validators review it, administrators approve/schedule it, and the system later publishes to the DASIG Facebook Page.

See `README.md`, `TASKS.md`, and `docs/` for project context, SRS, SDD, and task status.

```bash
npm install
npm run dev
npm run build
npm run lint
npm run preview
```

Vite dev server default: `http://localhost:5173`.

For local frontend-to-backend calls, create `frontend/.env.local`:

```env
VITE_API_URL=http://localhost:8080/api/v1
```

`frontend/.env.local` is intentionally ignored and should not be committed.

through backend-issued presigned URLs (see Architecture), so no `VITE_SUPABASE_*`
or storage keys are needed on the client.

## Architecture

DASIGConnect is a three-tier client-server system:

```text
React SPA (Vercel) -> Spring Boot REST API (Render) -> Supabase PostgreSQL + pgvector
                                                     -> Cloudflare R2 (S3-compatible object storage)
                                                     -> Facebook Graph API
                                                     -> Anthropic Claude
                                                     -> Voyage AI
```

**Object storage moved from Supabase Storage to Cloudflare R2.** `MediaStorageService`
wraps the AWS S3 SDK against any S3-compatible endpoint; config lives under
`app.r2.*` / `R2_*` (`R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`,
`R2_SECRET_ACCESS_KEY`, `R2_PUBLIC_BASE_URL`). The browser `PUT`s bytes straight
to an R2 presigned URL; the DB stores the public read URL. Supabase is now
**database only** (Postgres + pgvector). `DASIG_SUPABASE_SERVICE_ROLE_KEY` is kept
solely as a legacy read fallback in `ClaudeVisionClient` for old images still on
the private Supabase bucket.

### Backend - Spring Boot 4 / Java 21

- Entry point: `backend/src/main/java/com/dasigconnect/backend/BackendApplication.java`.
- Config: `backend/src/main/resources/application.properties`.
- Local env loading: `spring-dotenv` reads `backend/.env`.
- REST base path: `/api/v1`.
- Auth: stateless JWT through Spring Security and `JwtAuthenticationFilter`.
- Tenancy: institution scoping through `TenantScopeService` plus PostgreSQL RLS.
- DB migrations: Flyway in `backend/src/main/resources/db/migration/`.
- DB access: Spring Data JPA + Hibernate through HikariCP.
- Critical pool limit: keep Hikari max pool size at 5 for Supabase Session Pooler.

### Frontend - React 19 / TypeScript / Vite

- Entry: `frontend/src/main.tsx`.
- App shell: `frontend/src/app/App.tsx`.
- API clients: `frontend/src/api/`.
- UI: shadcn/ui, Radix UI, Tailwind CSS v4.
- Routing: React Router v7.
- HTTP: Axios with Authorization header managed by `setAuthToken`.
- Session expiry: `App.tsx` parses JWT `exp`, shows countdown banner near expiry, and opens the session modal at timeout.
- Media upload: browser requests a presigned URL from the backend, `PUT`s the file bytes directly to Cloudflare R2, then sends media metadata to the backend. No `@supabase/*` client or storage keys in the frontend.

## Use Case Status

This section summarizes each use case's status by UC number, replacing what used to be a dated, chronological session log (the narrative "what we did in session N" history has been removed — see git history / PR descriptions for that). **UC-1.1 through UC-1.4 and UC-1.10 have living, code-verified documents under `docs/md/`** (linked below) — those are the source of truth for their use cases; keep them and this summary updated together whenever a session changes code that touches them. Everything else below is carried forward from prior session notes and has **not** been independently re-verified against the current code this session — treat specifics (migration numbers, exact endpoint paths) as a starting point to confirm, not as current fact.

### Module 1 — Accounts, Institutions, Sessions

- **UC-1.1 Administrator Account Management** — see [`docs/md/UC-1.1-administrator-account-management.md`](docs/md/UC-1.1-administrator-account-management.md). Invite/promote/deactivate/reactivate/delete/erase an Admin account; a 3-admin cap (`app.admins.max`) enforced uniformly across invite, accept, promote, and reactivate; promotion to Admin is a propose/confirm flow, not instant; Admin Owner transfer.
- **UC-1.2 Institution Management** — see [`docs/md/UC-1.2-institution-management.md`](docs/md/UC-1.2-institution-management.md). Create/edit/deactivate/reactivate/permanently-delete an institution; the protected network-default institution ("DASIG Central Visayas") is exempt from both deactivation and deletion; Contributor reassignment between institutions.
- **UC-1.3 Contributor Account Management** — see [`docs/md/UC-1.3-contributor-account-management.md`](docs/md/UC-1.3-contributor-account-management.md). Invite/deactivate/reactivate/delete/erase a Contributor account; Moderators may only manage invitations they personally sent; re-inviting any deactivated account (any role) is blocked and must go through Reactivation.
- **UC-1.4 Login & Session Management** — see [`docs/md/UC-1.4-login-session-management.md`](docs/md/UC-1.4-login-session-management.md). JWT sessions (8h TTL) carry role + tenant scope; session revocation is persisted (`revoked_tokens` table for single-token logout, `users.session_version` for account-wide), enforced inside `JWTService.extractClaims` for every caller; only a password **reset** (not an authenticated password change) invalidates other sessions; Facebook Messenger notification linking is a 10-minute link-code sent via Messenger (not OAuth), open to Moderators and Admins; Analytics is available to all three roles (role-scoped, not Admin-exclusive) — everything else under Admin Management/System Health/Audit Log/Page Settings/Watermark Configuration is Admin-only.
- **UC-1.5 Post Drafting & Templates** — see [`docs/md/UC-1.5-post-drafting-templates.md`](docs/md/UC-1.5-post-drafting-templates.md). The 3-step composer (Media → Details → Schedule) used by contributors, moderators, and admins; readiness checklist with a 0–100 score; built-in + personal Save-as-Template; autosave; withdraw. Scheduling guard rails are a **network-wide runtime switch** (`page_settings.guardrails_enforced`, toggled in Settings → Page, read via `GuardRailSettingsService` and surfaced to the composer through `/submissions/lookups`). It governs the *rules* on a scheduled time, not whether one is picked: a Standard post always needs a future slot and a `SlotReservation`; when off, the ±30-min spacing / ≤6-per-day / ≥2h-lead / 8 AM–8 PM checks are skipped.
- **UC-1.6 AI & Text Tools Integration** — see [`docs/md/UC-1.6-ai-text-tools.md`](docs/md/UC-1.6-ai-text-tools.md). `POST /api/v1/ai/caption` (Claude `claude-haiku-4-5`, 30 s timeout, ≤4 images, >5 MB in-memory downscale) returns **one** caption for a chosen tone (`professional`/`community`/`energetic`); 30 requests/hour per user (in-memory limiter → `429`); 280-char prompt cap; interaction telemetry via `/ai/caption/log`. `FancyTextTool` is a button-opened panel (not auto-on-selection) with 5 Unicode styles + Plain revert. Both tools need a saved draft and work in Fast-Track; both are hidden only on read-only submissions. The stored-caption ceiling is **3000 characters** (code points) on both ends — frontend `CAPTION_CHAR_LIMIT` (`features/submission/utils.ts`, imported by `FancyTextTool`), backend `SubmissionService.MAX_CAPTION_CHARS` (`validateCaptionCharLimit`, 400 on create/update, 422 on submit). `ClaudeVisionClient.MAX_REQUESTED_CAPTION_WORDS = 2000` is a separate prompt-parsing guard on the requested word count, not the stored-caption limit. The AI caption context no longer includes a submission category — `Submission.category` was always `null` from the composer (`toPayload()` hardcodes `category: ""`; there is no category input field), so it was removed from `ClaudeVisionClient`/`CaptionGenerationService`'s Claude prompt-building end to end. `Submission.category` itself is untouched — still used by built-in post templates and UC-3.3 media-suggestion re-ranking.
- **UC-1.7 Media Attachment Rules** — see [`docs/md/UC-1.7-media-attachment-rules.md`](docs/md/UC-1.7-media-attachment-rules.md). Device upload (JPEG/PNG/WebP/GIF images, MP4/MOV/WebM video, ≤50 MB); library selection (UC-2.2); AI-suggested media (Voyage embedding, pgvector, 0.40 score floor, top 8, gated on ≥10 combined chars of event context); per-asset caption (≤500 chars) and image-only skip-watermark via the Media Caption modal; mixed image+video is accepted as a draft but fails automated publishing (`FacebookPublisherService`) and routes to the Approval Queue's Failed tab (UC-2.4) for manual recovery. **Album Auto-Match is now real AI matching**: `AIRecommendationService.suggestAlbum` (`POST /ai/submissions/{id}/suggest-album`) blends tag overlap with "closest existing asset" visual similarity (Voyage + pgvector, max score across a root album's assets, not a centroid) — confident (≥0.55) auto-applies with a reason badge, ambiguous (≥0.32) lists up to 3 ranked candidates inline in `AlbumCombobox`, otherwise the field is left for manual select/create.
- **UC-1.8 Engagement Helpers** — see [`docs/md/UC-1.8-engagement-helpers.md`](docs/md/UC-1.8-engagement-helpers.md). Peak-time recommendations (`EngagementRecommendationService`) come from real Facebook Graph API history (last 100 posts, reactions+comments+shares, 8 AM–8 PM window, Asia/Manila) — top 5 (day, hour) buckets by average engagement, needing ≥20 samples or a Tue/Wed/Thu 6 PM default is used; up to 3 future slots over a 30-day lookahead, each pre-filtered against guard rails (hard-blocked candidates excluded, not flagged); panel is skipped entirely for Fast-Track drafts and hidden outright if the Facebook analytics call fails. A manually-typed (non-recommended) time's soft guard-rail warnings now surface inline next to the date/time fields (`.sub-inline-warning`, gated on `lookups.guardrailsEnforced`) — same pattern already used for reviewer reschedules in `ValidationQueueScreen`/`ResolutionRetryModal`.
- **UC-1.9 Draft Submission** — see [`docs/md/UC-1.9-draft-submission.md`](docs/md/UC-1.9-draft-submission.md). `SubmissionService.submit()` moves `draft`/`needs_revision` → `pending` after `assertContentComplete` (title, date, caption, media, **album**) and, for Standard drafts only, a guard-rail re-check (`409` on conflict, e.g. UC-1.5's guard rails); Fast-Track skips the slot check entirely. Notifies **Moderators** (not Administrators) — T-01 in-app+Messenger for a standard submission, T-11 in-app+email+Messenger "urgent" for Fast-Track. Withdrawal is `pending`-only and blocked the instant a `ReviewLock` exists. A concurrent slot-conflict (`409`) at submit time now redirects the composer back to Scheduling instead of a generic toast, and Fast-Track submissions now sort to the top of the active Approval Queue (UC-2.4) on both ends — `findValidationQueue` orders `fastTrack DESC, scheduledAt ASC NULLS LAST, submittedAt ASC`, and `ValidationQueueScreen`'s own sort mirrors it (not applied in the "All" history tab).
- **UC-1.10 Moderator Account Management** — see [`docs/md/UC-1.10-moderator-account-management.md`](docs/md/UC-1.10-moderator-account-management.md). Network-wide (institutionless) Moderator invite/deactivate/reactivate/delete/erase; a Moderator may invite a Contributor to any institution but only manage invitations they personally sent; direct lateral role change between Contributor and Moderator.

### Module 2 — Content Workflow (UC-2.x) — *UC-2.1 has a living, code-verified doc; the rest below have not been independently re-verified this session*

- **UC-2.1 Library Uploads & Albums** — see [`docs/md/UC-2.1-library-uploads-albums.md`](docs/md/UC-2.1-library-uploads-albums.md). Standalone Media Library upload (`isAuthenticated()` — all three roles, not Contributor/Administrator-only): same 7-format/50MB validation as the composer, ≥1 tag required, Auto-Match is plain tag/filename text matching (no similarity score, no ambiguous tier — unrelated to UC-1.7's rebuilt composer Auto-Match, which this standalone flow doesn't share). Folder-style nested albums per institution; a shared default-institution library visible network-wide. **Known bug (unfixed):** no code path ever transitions an asset from `PROCESSING` to `READY` after successful AI classification — the "Processing…" badge never clears, and every `status = 'READY'`-gated feature (search, similarity, Auto-Match's visual score) silently excludes every asset uploaded since `V25`. Also: video uploads are never classified/embedded (image-only trigger), and an asset can never be fully unassigned from all albums (API rejects a null albumId).
- **UC-2.2 Media Asset Retention** — soft-delete with a configurable retention window (`MEDIA_ASSET_DELETED_RETENTION_DAYS`, default 30) purged by a daily job; bulk delete; per-asset deletion authorization is Admin-any / Moderator-institution / Contributor-own-uploads.
- **UC-2.3 Notifications** — SSE stream + REST CRUD, event-triggered in-app/email notifications, sidebar unread badge.
- **UC-2.4 Role-Scoped Analytics** — `/analytics` is reachable by all three roles; Contributor sees own submissions only, Moderator sees their institution, Admin sees network-wide with an institution filter.
- **UC-2.5 Watermark Configuration** — network-wide default plus per-institution overrides; Admin-only surface.

### Module 3 — Publishing & Exceptions (UC-3.x) — *not independently re-verified this session*

- **UC-3.1 Publishing Pipeline & Master Calendar** — scheduled Facebook Graph API publishing (2-step photo, single-call video) with retry/backoff; publishing is claimed (`scheduled → publishing`) before any Graph API call so overlapping scheduler runs can't double-post; role-scoped calendar view.
- **UC-3.2 AI Caption Generation** — Claude Vision-based caption suggestions with instruction-vs-draft-refine intent detection (typing a directive vs. a draft caption changes how Claude responds).
- **UC-3.3 AI Media Suggestions** — Voyage (`voyage-4-lite`, 1024-dim) embeddings + pgvector similarity search with hybrid category/tag/recency re-ranking, surfaced in the Submit Content media picker's AI Suggestions tab. Contributor-facing category/tag AI suggestion (as opposed to media suggestion) is intentionally out of scope.
- **UC-3.4 Manual Publishing Fallback (Resolution Center)** — a 3-step guided manual-publish workflow for submissions the automated pipeline couldn't post, with a 2-hour abandonment window.
- **UC-3.5 Administrator Exception Handling** — a 5-tab Resolution Center hub covering validation timeouts, override requests, admin direct posts, and Facebook token re-authentication.

### Known cross-cutting gaps

- Backend deployment runtime needs team-owned SMTP credentials configured on Render (infrastructure, not code).
- Per-type media file size limits (25 MB image / 500 MB video) require a Supabase Pro upgrade; the free tier is capped at 50 MB for all file types.

## Key Design Decisions

- JWT auth is stateless; do not introduce server-side sessions. Revocation, however, is DB-backed on purpose (`revoked_tokens` for single-token logout, `users.session_version` for account-wide) — enforced in `JWTService.extractClaims` so it survives restarts and holds across instances. Don't move it back into an in-process map.
- Tenant isolation is enforced in application services and PostgreSQL RLS.
- Flyway owns schema changes. Add migrations instead of relying on Hibernate DDL.
- Do not edit generated files under `backend/target`; fix migration conflicts in `backend/src/main/resources/db/migration`.
- `BackendApplication` custom Flyway/diagnostic beans are gated by `spring.flyway.enabled`; tests depend on this isolation.
- `MediaAsset.embedding` is not Hibernate-mapped because pgvector `VECTOR(1024)` is handled through native queries.
- AI Media Library now has a migration path toward `media_asset_embeddings` with separate `embedding_type` values (`image`, `semantic`, `keyframe`). Do not drop the old `media_assets.embedding` column until uploads, backfill, and suggestion search have been verified on the new table.
- Media upload: the frontend gets a presigned `PUT` URL from the backend, uploads the bytes directly to **Cloudflare R2** (S3-compatible, via `MediaStorageService`), then posts metadata to the backend. The backend never receives multipart file bytes. Object storage config is `app.r2.*` / `R2_*`; Supabase is database-only now.
- Submission media ordering is controlled by `submission_media_assets.display_order`; publishing queries already load assets ordered by this field. Use `PATCH /api/v1/submissions/{id}/media/order` for saved draft media reorder instead of mutating media asset records.
- Publishing is now claimed before any Facebook Graph API call. Preserve the atomic `scheduled -> publishing` / `direct_post_scheduled -> direct_post_publishing` transition so overlapping scheduler runs or multiple app instances cannot publish the same submission twice.
- Fresh Supabase `public` schemas should baseline Flyway at version `0`, not `1`; otherwise V1 is skipped and Module 1 tables are never created.
- Invitation links are treated as superseded when a fresh invite/resend is issued for the same email; do not leave multiple open invite links for one pending account.
- The frontend should display institution names from `GET /api/v1/me`; email-domain guessing is only a fallback.
- Do not increase HikariCP max pool size past 5 unless the Supabase plan/pooler changes.
- Do not log JWTs, passwords, reset tokens, invitation tokens, or API keys.
- `BackendApplication.flyway()` calls `repair()` then `migrate()` explicitly. Do not add `outOfOrder=true` or `validateOnMigrate=false` — fix schema history issues by renumbering migration files instead.
- When a migration file was never applied to a shared DB but a higher-version migration already was, do not reuse the old version number. Create new files at the next available version number.
- V4 creates `asset_tags` with columns `(asset_id, tag, source)`. V17 drops and recreates it with `(media_asset_id, label)` to match the `AssetTag` entity. Do not revert V17.
- Notification inserts in `SubmissionService.submit()` (T1 — notify validators) are wrapped in try-catch. This is intentional: a notification failure must never roll back the PENDING status transition.
- `SubmissionService.submit()` reconciles attached media with the finalised post: a new upload (STAGED, or any album-less asset — a real library pick always has an album) is bound to the institution, filed into the album resolved from `submission.albumName` (existing root album by name, else a new one) via `resolveSubmissionAlbum`, and set to PROCESSING for the AI pipeline; a library-picked asset keeps its original album. Both get the post's media tags (`applySubmissionMediaTags`, `manual` source, deduped by label). Do not re-home a library pick's album on submit.
